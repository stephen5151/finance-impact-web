# 金融事件生活影响推演 Web 设计文档

日期：2026-05-29

## 1. 项目目标

做一个面向年轻个人用户的网页产品，把最近一两个月的重要政治经济事件，翻译成普通人能理解的生活影响推演。

这个产品不试图给出投资建议，也不承诺精准预测市场。它的核心价值是：

- 帮用户看懂一件金融或政治经济事件，为什么会影响普通人的生活
- 帮用户理解影响是如何一步步传导的
- 帮用户判断哪些变化更可能先发生，哪些变化只是中期风险
- 用通俗表达回答“这会不会影响我”

全站固定声明：

`本网站仅用于信息理解与生活影响分析，不构成投资建议。投资需谨慎。`

## 2. 目标用户

第一版默认服务对象：年轻个人。

重点覆盖的生活维度：

- 找工作与就业机会
- 工资与收入稳定性
- 租房与生活成本
- 日常消费价格
- 存钱与现金流压力
- 基础理财认知

第一版不重点覆盖：

- 专业投资者
- 企业财务决策者
- 宏观研究从业者
- 复杂资产配置需求

## 3. 产品定位

这是一个“双入口”的解释与推演网站。

入口一：最近事件

- 展示最近一两个月的重要政治经济事件
- 用户点进事件后，查看结构化推演内容

入口二：直接提问

- 用户直接输入“这会对我有什么影响”
- 系统根据问题识别事件主题与生活维度
- 输出通俗、结构化的影响解释

本产品第一版的重点不是“预测准不准”，而是“推演路径是否清楚、表达是否易懂、内容是否可信”。

## 4. 第一版范围

### 4.1 要做的内容

第一版包含以下能力：

1. 首页展示最近事件列表
2. 用户点击事件进入详情页查看推演
3. 首页提供提问框
4. 用户可输入类似“美联储加息会影响我找工作吗”的问题
5. 系统输出与年轻人生活相关的影响解释
6. 全站加入风险提示与非投资建议声明

### 4.2 第一版不做的内容

第一版明确不做以下内容：

- 实时行情
- 个性化投资建议
- 账户系统
- 用户画像长期记忆
- 复杂概率模型可视化
- 精准量化预测
- 多角色模式切换

> 说明：原先列入“不做”的「自动抓取并持续更新新闻」与「接入大模型」，已升级为 V2 的核心方向，详见第 13 章。

## 5. 核心内容结构

### 5.1 最近事件卡片

首页展示 6 到 10 个最近一两个月的重要事件。每张卡片至少包含：

- 事件标题
- 事件发生时间
- 一句话解释
- 主要影响方向标签
- 影响对象标签

示例事件类型：

- 美联储加息或降息
- 国际油价上涨
- 通胀回升
- 房地产政策变化
- 地缘政治冲突升级
- 出口或制造业数据走弱

### 5.2 事件详情页固定结构

每个事件详情页统一采用同样结构，避免内容忽深忽浅：

1. 这件事发生了什么
2. 为什么这件事重要
3. 它通常会先影响什么
4. 它会怎样一步步传导到普通人的生活
5. 对年轻人的重点影响
6. 短期更可能发生什么
7. 中期需要留意什么
8. 哪些人更容易感受到影响
9. 这不代表什么
10. 风险提示

### 5.3 直接提问结果结构

用户提问后，结果页统一用以下方式组织：

- 先用一句话直接回答
- 再解释为什么
- 再按生活维度展开
- 最后提醒不确定性和适用范围

建议输出结构：

1. 直接回答
2. 影响路径
3. 对工作的可能影响
4. 对消费的可能影响
5. 对租房和生活成本的可能影响
6. 对存钱和现金流的可能影响
7. 哪类年轻人更受影响
8. 当前更值得关注的信号
9. 风险提示

## 6. 推演表达原则

内容表达必须遵守以下原则：

### 6.1 用“路径”解释，不用“结论”压人

不要直接说“会导致失业”。

应表达为：

- 某个事件先影响资金成本、企业利润或运输成本
- 再影响企业招聘、价格、消费意愿或行业景气
- 最后才传导到年轻人的工作、收入或支出

### 6.2 用“更可能”表达，不装作确定预言

避免使用绝对化表达，例如：

- 一定会
- 必然会
- 马上会

优先使用：

- 更可能先出现
- 有较大概率影响
- 短期未必立刻体现，但中期可能传导

### 6.3 用生活语言，不用专业堆砌

把抽象金融语言翻译成普通人能理解的话。

例如：

- “流动性收紧”翻译成“钱变贵了，借钱和融资更难了”
- “输入型通胀压力”翻译成“从海外传进来的涨价压力，会让国内部分商品更贵”

## 7. 页面设计

### 7.1 首页

首页目标：让用户一眼知道这网站能帮他什么，并快速进入事件或提问。

首页模块建议：

1. Hero 区
2. 风险提示条
3. 最近事件区
4. 提问框区
5. 推演说明区
6. 适用对象说明

Hero 区核心文案方向：

- 看懂最近大事，推演它会怎样影响你的生活
- 不是教你炒股，而是帮你理解未来可能发生什么

### 7.2 事件详情页

详情页目标：把一个复杂事件拆成普通用户能一路看懂的因果链。

页面表现建议：

- 顶部先给一句话结论
- 中间给影响路径流程
- 下方按生活维度展开
- 结尾给风险提示和适用边界

### 7.3 提问页或提问结果区

提问入口建议放在首页明显位置。

问题示例：

- 油价上涨会影响我找工作吗
- 美联储加息会影响我存钱吗
- 通胀上升会让我生活更难吗

结果展示应避免像聊天记录，更像清晰回答卡片。

## 8. 内容组织方法

为了保证内容稳定可维护，第一版建议采用“结构化事件内容 + 问题映射”的方式。

也就是：

- 先准备好一批结构化事件
- 再把用户问题映射到这些事件和生活维度
- 最后生成对应回答

这样做的原因：

- 内容更稳定
- 不容易出现空泛答案
- 更容易人工校对
- 更适合第一版快速上线

## 9. 信息可信度边界

网站必须主动告诉用户边界：

- 这是基于公开事件的生活影响解释，不是未来保证
- 不同行业、地区、收入状态，感受到的影响会不同
- 短期市场波动不等于生活层面的立即变化
- 内容只能帮助理解趋势，不能替代个人投资或重大财务决策

## 10. 最小可用版本定义

第一版完成标准如下：

1. 用户打开首页，能立刻看懂网站用途
2. 用户能看到最近事件列表
3. 用户能点开至少 6 个事件查看完整推演
4. 用户能输入问题并得到结构化回答
5. 页面明确展示非投资建议声明
6. 文案表达通俗，不依赖金融背景

如果以上 6 条都成立，则第一版可以视为可上线原型。

## 11. 后续可扩展方向

第一版完成后，可考虑的增强方向包括：

- 增加“你属于哪类年轻人”的角色切换
- 增加时间线视图
- 增加影响程度标签，例如高、中、低
- 增加不同事件之间的关联推荐
- 增加更多问题示例与热问榜
- 增加按生活主题浏览，而不是只按事件浏览

## 12. 推荐实施路线

建议按以下顺序实现：

1. 先做首页结构和品牌表达
2. 再做事件详情页模板
3. 再填入一批样例事件内容
4. 再做提问入口和结果页
5. 最后统一补风险提示、空状态和视觉优化

这个顺序能确保产品先有“可看内容”，再补“可问交互”，避免一开始把重点放在复杂问答逻辑上，导致成品空心化。

## 13. V2 架构升级（混合模型 + 实时新闻）

第一版采用“关键词匹配 + 全静态文案”，内容稳定但存在三个问题：同一事件永远返回同一答案、问法稍变就识别不到、事件库静态不更新。V2 在不牺牲可信度的前提下解决这些问题。

### 13.1 核心原则：混合架构，模型负责理解，不负责下结论

V2 采用“模型理解 + 人工审核内容”的混合方式，明确分工：

- **模型负责（动态、灵活的部分）**
  - 理解用户用自然语言提出的问题（语义理解，不再靠字符串包含）
  - 把问题匹配到最相关的结构化事件与生活维度
  - 对实时抓取的新闻做筛选、去重、摘要和结构化
  - 在给定事实和约束下，组织通俗、口语化的表达

- **人工/规则负责（稳定、可信的部分）**
  - 事件的核心结论、传导路径、影响人群仍以审核过的结构化内容为准
  - 模型输出必须落在预置事实与表达原则（第 6、9 章）的边界内，不得自由发挥出新的“预测”或“投资建议”
  - 全站风险提示与非投资建议声明保持强制展示

这样做的收益：保留第一版“内容可信、可校对”的优点，同时获得“能听懂多样问法、内容能更新”的灵活性。

### 13.2 模型接入方式

- 模型通过 **HTTP API** 调用，运行在 Next.js 服务端（Vercel Serverless / Edge Function）中，密钥仅存于服务端环境变量，不暴露给前端。
- 可选方案：
  1. 商用托管 API（首选）—— Claude / OpenAI / DeepSeek / 通义千问 / 智谱 GLM 等，按量付费、零运维。
  2. 自部署开源模型（Llama / Qwen / DeepSeek 等）—— 需自备 GPU 推理服务，**访问方式仍是 API endpoint**，成本与运维更高。
  3. 浏览器端模型（WebLLM / transformers.js）—— 不走服务器，但模型能力与加载体积都不适合本产品，暂不采用。
- 第一版选型建议：**优先 Claude API**（中文与文案质量好），DeepSeek 作为低成本备选。
- 抽象出统一的 `llm` 调用层，便于后续切换供应商。
- 必须处理：超时、失败兜底（降级回 V1 的静态匹配结果）、调用频次与成本控制、输出格式校验。

### 13.3 实时新闻接入与自动更新

目标：最近事件列表不再写死，能定期自动滚动更新最新时政与财经事件。

推荐数据源（优先选有 RSS 或 API、便于自动抓取的）：

- **官方时政 / 政策（权威、免费）**：中国政府网 gov.cn、国家统计局 stats.gov.cn（CPI/PPI/GDP 数据接口）、中国人民银行 pbc.gov.cn（货币政策与利率）、新华网 / 人民网。
- **财经媒体**：财联社（快讯时效强）、第一财经、财新网、东方财富、新浪财经（资讯+行情接口）。
- **国际**：路透中文、FT 中文网、彭博（美联储、油价、地缘）。
- **聚合 API（省事）**：NewsAPI.org、GNews.io（英文为主，有免费额度）；聚合数据、天行数据（中文新闻 API）。

自动更新流程：

1. **定时触发**：用 Vercel Cron Jobs 按固定频率（如每天 2–3 次）调用更新函数。
2. **抓取**：从上述源拉取最新条目（RSS / API）。
3. **加工**：交给模型做去重、筛选出对年轻人生活有影响的事件，并按第 5.2 节固定结构生成结构化推演草稿。
4. **发布策略：可信源自动发布**：来自可信源（官方时政/政策、权威财经媒体）的内容经模型结构化后自动上线，不卡人工审核，以保证时效；同时维护一份“可信源白名单”，只有名单内来源走自动发布，名单外来源仍需人工确认。每条自动发布内容标注来源与更新时间，便于追溯。
5. **存储**：结果写入数据库 / Vercel Blob / Edge Config，前端读取展示。
6. **标注**：每个事件标明数据来源与更新时间，便于用户判断时效。

### 13.4 V2 范围边界（仍然不做）

- 仍不做实时行情、个性化投资建议、账户系统。
- 模型不得脱离审核内容自由生成“预测”或“买卖建议”。
- 自动抓取的新闻仅当来源在可信源白名单内才自动发布；名单外来源不直接面向用户展示，需人工确认。

### 13.5 V2 实施顺序建议

1. 抽象 `llm` 调用层，先用模型替换提问页的关键词匹配（理解 + 匹配事件），结论仍取静态文案，并保留 V1 降级兜底。
2. 接入 1–2 个稳定数据源 + Vercel Cron，实现最近事件的自动抓取与摘要，先走“人工审核后上线”。
3. 引入存储层，将事件从静态文件迁移到数据库 / Blob。
4. 逐步放开自动发布、扩充数据源、加入来源与更新时间标注。
